# docs/ —— 文档体系说明（入口导航）

AI Asset Hub 文档体系 = **三层一表 + 单向引用链**：规范层（系统形态，常青）·
设计层（阶段决策档案）· 计划层（实现任务清单）· 追踪表（里程碑状态唯一源）。
体系的权威定义在 `00-product-direction.md` §7；本文件是 docs/ 的**入口与路由**——
docs/ 里有什么、新文档放哪层、文档怎么流转。规则细节一律指路不复制（防漂移）。

## 3. 新文档放哪层（判定树）

```text
要写的文档是「系统长什么样/协议契约」（跨里程碑稳定）？── 是 → 规范层 docs/NN-*.md
                                                        否 ↓
是里程碑内的阶段决策（技术选型/状态机/UX，需拍板）？── 是 → 设计层 designs/YYYY-MM-DD-<主题>-design.md
                                                        否 ↓
是实现任务清单（怎么一步步做 + 验收断言）？────────── 是 → 计划层 plans/<里程碑>-<主题>.md
                                                        否 ↓
都不是 → 停下先问：这份文档真的需要吗？
```

放错层的典型症状与修正：决策写进 plan 而不落 design（引用链断）、系统契约散进 designs/
（跨里程碑漂移）——收尾 converge 重评会暴露这类偏离（见 §5）。

## 4. 引用链与状态

- 引用链**单向**：`plan → design → 规范 §N`——引用不复制，改规范只动一处。
- **拆批里程碑的文档模型**：1 份**主 design**（跨批不变层：里程碑范围 / 模型与角色契约 / 路由清单 / 视觉基线归属 / 拆批表 / 决策登记）+ N 份**批 design**（批内决策）+ 对应**批 plan**（任务）。批内内容随批**迁出**，主 design 留指针。
- **批 design 可先于主 design 定稿**：主 design 的定稿条件由其自身 Status 列明（如 M4b 主 design 的「② 三族适用性实证」随 M4b-5 闭合）；**批 design 各自 8 维自检 ≥9 即可先行定稿并立 plan**，不必等主 design 转定稿。
- 状态**唯一源**：里程碑状态以 00 §5 为准（出口标准：相关 design 8 维 ≥9 定稿 +
  计划 Task 全绿 + 代码验证通过，三项齐备才翻 ✅）。
- 工作指南：`AGENTS.md`（仓库根）——命令/协作约定/操作限制，文档体系的执行侧。

## 5. 文档生命周期

```text
草稿 → 8 维自检 ≥9 → grilling → 定稿（Status 定稿 + 修订记录）
   → 实现（plan Task 断言为真）→ converge：里程碑收尾文档-代码对齐回查 + 8 维重评 ≥9
```

纪律要点：版本头 Updated 与修订记录最新版同步；修订记录只追加新行；被否决的方案/
概念不写入文档；同主题小迭代追加既有文档（bump 版本），不新建散文档。
