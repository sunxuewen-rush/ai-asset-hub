# AI Asset Hub 产品定位与方向

> Date: 2026-09-04
> Status: Draft（设计阶段，未动代码）
> Scope: 全新开源项目 —— AI 资产注册中心与市场（技能/MCP/Worker 多类型资产）

## 1. 定位

AI Asset Hub 是**开源的企业级 AI 资产注册中心与市场**：技能（Skill）、MCP Server、Worker 等
AI 可复用资产，从发布、审核、发现到安装使用的统一分发平台。自托管优先，面向防火墙内
的企业/团队部署，也适合个人与社区使用。

一句话：像「内网 npm 之于 AI agent」——skillhub 的治理哲学 × Den 的多类型资产架构 ×
全开源（Apache 2.0）。

### 1.1 市场坐标（为什么存在）

| 现有方案 | 单/多类型 | 授权 | 与我们的差异 |
|---------|----------|------|-------------|
| skillhub（iflytek） | 单类型（skill） | Apache 2.0 | 无多类型资产；Java 栈 |
| Den/OpenWork | 多类型（11 种） | FSL-1.1（ee/ 有商业边界） | 资产市场只是其全家桶一部分；非全开源 |
| HiMarket | 多类型（7 种） | Apache 2.0 | 阿里系网关控制面形态，绑定 Higress/APIG 生态 |
| ClawHub / OpenSkills | 单类型 | - | 客户端生态/注册面，非完整治理平台 |

AI Asset Hub = 多类型资产原生设计 + 开放协作审核治理 + TS 全栈 + 真开源（Apache 2.0），
在当前开源生态中无直接同类。

## 2. 核心范围

### 2.1 资产类型（原生 type 设计）

首期三类，未来按「类型登记 + 族协议文档」模式扩展：

| type | 包形态 | 消费方式 |
|------|--------|---------|
| `skill` | SKILL.md + 资源目录（兼容 OpenSkills/Claude 约定） | 安装进 agent 技能目录（`.agents/skills` 等） |
| `mcp` | 双形态：远程 = 连接配置（url/headers）；本地 = stdio 声明 + 实现脚本 | 配置进客户端 MCP 配置区 |
| `worker` | 执行体 bundle：manifest + 启动入口 + 可选预装 skills + 运行时声明 | 安装进 Worker 运行时，可加载技能执行 |

类型扩展规则：`skill` 表（或等价资源表）type 枚举 + 各族协议文档（zip 布局/manifest/校验器）
+ 前端内容视图组件 —— 模式固定，新类型只是再走一遍。

### 2.2 治理模型（继承团队拍板过的设计）

- 命名空间坐标 `@namespace/slug`：团队空间 + 全局空间，slug 跨类型唯一
- **开放协作**：任何人可向任意资产提交更新；非 owner 提交走 `PENDING_REVIEW` 审核；
  owner/空间管理员审核；全局空间由平台管理员治理 —— Git 式协作，非 owner 独占
- 生命周期：draft → PENDING_REVIEW → PUBLISHED → 下线/归档；版本化 + 标签通道（latest 只读，回滚走自定义标签）
- 安全：发布前置校验器（按 type 插拔）+ 安全扫描扩展点 + 全链路审计

### 2.3 消费与兼容

- CLI：安装/发布/搜索/认证（Device Flow 风格），一条命令装到对应位置
- 兼容边界：`skill` 资产承诺 OpenSkills/Claude 目录约定互操作；`mcp`/`worker`
  为平台原生协议，不承诺第三方格式（必要时可加导入适配器，非首期）
- 公开资产匿名可浏览/下载（企业内网默认形态）

## 3. 关键决策（决定板）

| # | 决策 | 结论 | 理由 |
|---|------|------|------|
| D1 | 项目形态 | 全新自研开源项目，不做 skillhub 扩展 | skillhub 为 skill 单域深度耦合（72/193 domain 类），扩展代价高且绑定 iflytek 上游 fork |
| D2 | 名称 | AI Asset Hub | 直白表达定位；GitHub 同名无威胁 |
| D3 | License | Apache 2.0 | 全开源；对齐 agent 生态惯例 |
| D4 | 技术栈 | TypeScript 全栈（Hono + Drizzle + PostgreSQL；React 19 + Vite；zod） | 资产协议生态与 Den 架构参照同语言；协议校验 zod 表达力强；前后端同栈 |
| D5 | 多类型 | 原生 type 设计（非单一聚合根打补丁） | 从零项目无历史包袱，一次到位 |
| D6 | 治理 | 开放协作 + PENDING_REVIEW（非 owner 独占） | 团队已验证的协作哲学；离职场景可持续维护 |
| D7 | 用户体系 | 产品自带（本地账号 + SSO/OIDC 适配） | 开源产品须可独立部署；内网与 skillhub 用户打通是部署期集成选项，非产品代码 |
| D8 | Clean Room | 架构借鉴 Den/skillhub，代码全部新写 | Den(ee/) 为 FSL，禁止复制其代码入开源仓库 |
| D9 | 与 skillhub 关系 | 并行独立；可选提供迁移工具 | skillhub 继续服务存量；新平台渐进替换 |

## 4. 设计原则

- 协议即 schema：资产包协议用 zod 单一定义，前后端共用，manifest 校验一致
- 治理优先：审核/审计/安全是分发平台的立身之本，功能可砍，治理不砍
- 类型是维度：一套版本/审核/标签/搜索管线服务所有类型，类型只决定「包怎么验、怎么展示」
- 兼容省心：skill 资产吃 OpenSkills/Claude 生态约定，迁移成本最低
- 单仓库：server + web + cli + docs 一体演进（参考 skillhub 单仓库习惯）

## 6. 首期非目标

- 多租户 SaaS、计费/额度体系（那是网关层的事，不做）
- 在线资产编辑器
- 社交面（评分/评论/关注）—— 只保留下载统计与收藏所需最小集
- 与 Den/ClawHub/OpenSkills 服务端的协议级互联（格式兼容即可，互联后置）
- 云托管服务（开源自托管优先）

## 7. 文档体系（规划）

协议规范：`00` 本文档 · 资产协议总纲（N1）· 各族协议（skill/mcp/worker，N2+）
设计文档：`YYYY-MM-DD-<主题>-design.md`（阶段性设计，含 8 段骨架）
命名/元信息/修订记录规则沿用团队在 skillhub 沉淀的文档习惯。
