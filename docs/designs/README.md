# designs/ —— 设计层

存放**阶段性设计文档**（记录「为什么这么做」= 阶段决策），与规范层隔离。

- 命名：`YYYY-MM-DD-<主题>-design.md`（日期前缀 + `-design` 后缀）
- 触发：里程碑内出现需拍板的设计块（技术选型/状态机/UX 线框）
- 骨架：7 段（元信息/修订记录/正文/接口变更总览/UI-UX 变动/线框图/引用文件清单）
- 任务清单不属本层：设计驱动的实现细则一律落对应 plan（docs/plans/），design 不复制——
  正文可按需加「验收口径」「后置延伸」小节（非强制段）
- 门禁：8 维自检 ≥9 → grilling → 重评 ≥9
- 合并铁律：同主题小迭代追加既有 design（bump 版本），不新建散文档
- **实施期发现（F 号）登记规则**（2026-09-24 定 · 依据 00 §7 ②「findings 逐条登记 + 处置，不留未决项」）：
  - **号**：**全局连续**（跨批不重置）· 按**登记时间**分配 = 当前最大号 + 1 · **跳号/预留必须在总览注明原因**
    （现存空洞 F39 / F40 / F144–F148 / F197–F202 —— 全仓零命中、原因未知，已标注在 `docs/README.md` §6.1）
  - **明细主家 = 批 design 的固定小节「实施期发现与处置（F…）」**（表列 `号 | 面 | 问题（真） | 处置`）；
    **批 plan 与证据文件只放指针/一行摘要**（写法沿用 M4b-4「明细见批 design §11.9」）—— 同一事实不两处长写
  - **用户报缺陷免号**：沿用既有惯例，用户报缺陷可在批 plan 加 `T<n>⁺` 行（先例 T10⁺ = F206），不占新 Task 编号
  - **跨批总览（指针表）** 在 `docs/README.md` §6.1 —— 本层只定义规则，不复制总览
- **拆批里程碑**：**主 design**（跨批不变层）留在 `designs/`；**批 design** 命名 `YYYY-MM-DD-m4b<n>-<主题>-design.md`；批内内容随批迁出、主 design 留指针（不双写）

体系定义见 `docs/00-product-direction.md` §7。
